# 硬件可行性评估：Allegro「抓握药瓶 + 拇指按压喷嘴」

> 状态：**几何不可行（Stage0/1 已做完，按计划在 Stage1 止损，未跑 Stage2 力量 / Stage3 自由瓶）**
> 日期：2026-09-04
> 评估对象：`KUKA_ALLEGRO_CFG`（KUKA iiwa7 + 16-DoF Allegro 手）抓握 Ø44×100 mm 药瓶瓶身，同时用某根手指（原设想=拇指）按下顶部弹簧喷嘴。
> 触发口径：喷嘴行程 ≤ −0.0035 m（≈ 全行程，压到底需 ≈ 8 N，弹簧 K=2000）。

---

## 0. 结论摘要

在 **机器人可达的工作空间窗口** 内，找不到任何一种「手同时环抱瓶身 + 另一根手指/拇指压顶」的姿态：
手只能以「瓶正上方、手指近似竖直朝下」的姿态到达药瓶附近，此时若一根手指去压喷嘴顶，其余三根手指悬在瓶口上方（指尖 0.60–0.73 m，瓶身只到 0.54 m），**收拢它们反而朝外抬**，够不到瓶身；把整只手放到瓶身侧面做水平环绕（palm 侧向朝瓶）则 **IK 不可达**（残余 200–860 mm）。

根因是几何性的：喷嘴比瓶身上缘高出 ~45 mm，而四根手指近似等长、又在平行平面内屈曲 —— **要压到喷嘴，手必须抬得比瓶口高 4–5 cm，瓶身就落到了手指够不着的下方**；Allegro 又不能在竖直圆柱体背面「逐指环绕」（所有屈曲轴平行），所以两个动作无法在一次握持中同时成立。

→ **按计划在 Stage1 止损**。以下给出量测依据与替代路线。

---

## 1. Stage0：手几何标定（sim，`scripts/geom_probe.py`）

以 `palm_link` 为基准体的量测：

| 量 | 值 |
|---|---|
| 指节长（index/middle/ring） | palm→MCP 0.056–0.075 m；近节 0.054 m；中节 0.0384 m |
| thumb 全长（palm→指尖） | ≈ 0.157 m |
| 四指屈曲轴 | 全部 ≈ palm −y（平行），joint_0 外展 ≈ +x；thumb joint_0 对掌、joint_1 轴 ≈ +z |
| 长指指尖全展半径（palm 系） | 开放 ≈ 0.15 m → 全握 ≈ 0.06 m |
| 对掌最近 tip-tip | **middle–thumb ≈ 41 mm**（< 瓶 Ø44，勉强够但余量极小） |

含义：四根长指在**平行平面**内屈曲，无法对 Ø44 圆柱体做「各指绕到背面的逐指环绕」；能实现的只有「指腹/指尖从一侧压 + 拇指对侧压」的类捏持，且 Ø44 已接近手的最小闭合量（41 mm）。

## 2. Stage1：可达 / 接触扫描（药瓶固定，`scripts/eval_grasp_reach.py`, `eval_side_wrap.py`）

### 2a. 过顶按压族（presser = index / thumb），DLS-IK 把指尖送到瓶中心上方再下探
| presser | align 残差 | 下探后指尖 | 同时把其余手指收到 curl 1.0→1.7 |
|---|---|---|---|
| index | ~41 mm | tip_z 0.603，径向 ≈22 mm（瓶口边缘，非中心） | 其余指尖径向 77→105 (middle)、96→136 (ring)、~150 (thumb)，**始终不贴瓶身** |
| thumb | ~95 mm | tip_z 0.582≈喷嘴顶，但径向 ≈54 mm（**压不到 Ø22 喷嘴**） | 三长指最近 53 mm、z 0.61–0.65（在瓶口上方），**够不到瓶身** |

要点：手从上方下来时，四指尖都悬在瓶口上方（瓶身只到 z=0.54，指尖在 0.60–0.73）；一收拢手指，指尖**向外/向上**抬离，不向瓶身包卷。

### 2b. 侧向环绕族（palm 在瓶身一侧、手指水平指向瓶，`eval_side_wrap.py`）
对瓶身 6 个方位×高度×掌杯朝上/下 的候选 palm 目标做 IK，**全部不可达**（位置残差 200–860 mm），与既有 `probe_reach` 结论一致：该机械臂在瓶位附近只允许「手指近似竖直」的手姿态，不允许水平环绕的姿态。

### 判定
**不存在几何上可达的「环抱瓶身 + 另一指压顶」组合**。唯一可达的按压方式是被 Phase1 验证的**上方直下压**（index 指尖压喷嘴），而它在几何上无法同时提供瓶身环抱。

## 3. 为什么不可行（根本原因，供动作重设计）

1. **喷嘴高出瓶口 45 mm**：压顶时手掌/四指须悬在瓶口上方 ~45–60 mm；手指近似等长，悬在喷嘴高度就碰不到 45 mm 下方的瓶身。
2. **可达手姿态单一**：工作空间只给「过顶、手指朝下」一族；侧向水平手不可达（`probe_reach` 亦证实）。
3. **无逐指环绕**：四指屈曲轴平行，竖直圆柱背面无法被手指各自包住；只能单侧压+对侧拇指顶，且 Ø44 ≈ 手最小闭合 41 mm，余量 ~0。
4. 即使是**单手稳定握持瓶身**这一子目标，在本工作空间内也未测得可达姿态。

## 4. 对 Phase 2（动作定义）的意义

- 「抓握→按压」两段式作为**同一只手、一次握持内完成**：不成立。
- 「按压喷嘴」单独成立且已被 Phase1 演示（index 过顶下压至 −0.0035，松开回弹）。
- 若要保留「压顶」作为目标动作，Phase 2 奖励/动作空间应按 **Phase1 式过顶按压** 定义，把「抓握」弱化为「手指在瓶口附近的稳定接触/限位」，而非刚性环抱。

## 5. 替代路线（按推荐序，待用户拍板）

- **A（推荐）** 采纳「过顶按压」为唯一按压姿态族（Phase1 已验证可达 + 压到底），把 Phase 2 的 RL 目标定为「多指过顶接近 → index 压顶 → 松指回弹」，不追求拇指压/环抱。
- **B** 若坚持「手环抱瓶身」：重扫**药瓶摆放位/桌高**，寻找能让手臂以水平手姿态到达的窗口（工作空间是否给「侧向」取决于瓶位，需专项重扫——现默认瓶位给不了）。
- **C** 若坚持「拇指压顶」：几何上需拇指以「过顶拱起」姿态落在 Ø22 喷嘴正中；现量得 thumb 过顶残差 ~54 mm，**即便固定瓶也不可信**，需先证明能对中，再谈力量。
- **D** 换触发设计：降低弹簧所需力 / 让喷嘴与瓶口齐平 / 增大喷嘴顶面积，使「够得着」与「握得住」的高度差消失。

## 7. 换更高灵巧手能否解决「抓握 + 按压」？（2026-09-04 用户问询）

> 用户问：若把 Allegro 换成自由度更高、更灵巧的手（更强对掌/独立指节等），是否就能让「一次握持内环抱瓶身 + 拇指压顶」成立？
> 判定：**部分能、部分不能**。灵巧度能修「灵巧类」瓶颈，但修不了「尺寸 / 臂工作空间 / 力量类」瓶颈——单独换手不足以推翻 §0 的不可行结论。

### 7.1 按失败原因拆解「换手能修 / 不能修」

| 失败原因 | 换更高灵巧手能否修复 | 说明 |
|---|---|---|
| 等长四指同面屈曲，压顶时手悬在瓶口上方，其余指够不到下方 45mm 瓶身 | **部分可修（靠指长/指型分工，不靠自由度）** | 需要「一根指够到喷嘴顶 ≈0.585、同时其余指仍包住下方瓶身带 0.44–0.54」的高度分工。自由度再多，若各指指尖等长同高，仍同时够不到两个高度。 |
| 瓶位附近工作空间只给「过顶、手指朝下」一族；侧向/水平环绕不可达（200–860mm） | **不能（Kuka 臂 + 瓶位问题，与手无关）** | 换手不改变机械臂在瓶位附近的姿态可达集；要么换臂/换瓶位（备选路线 B），要么接受过顶族。 |
| 四指屈曲轴平行，无法逐指绕到 Ø44 圆柱背面（§1：对掌最近 middle–thumb ≈41mm < Ø44，余量≈0） | **能（灵巧性核心收益）** | 带指外展/内收、独立指节、近人手运动学的手可逐指包卷/绕背；Allegro 各指只有 spread 在掌面内张开，绕不到背面。 |
| 拇指过顶对中不了 Ø22 喷嘴（§2a：残差 ~54mm） | **部分能** | 对掌锥更大、可「拇指跨过瓶口拱到喷嘴顶正中」的手可修；但仍受臂可达的手姿态族约束（上一行）。 |
| 压到底需 ≈8 N（弹簧 K=2000，见 §0），Allegro 指尖力量有限（sim effort 0.5 / 真机 ~0.7 N·m，单指尖 ~10 N） | **不能（灵巧 ≠ 力量）** | 需指尖持续力 ≥ ~8 N 且有裕量的驱动配置；纯增自由度不增力量。 |

### 7.2 由此反推的「替换手规格」（仅当整套重做时参考）

1. **指长/指型高度分工**：一根指（或拇指）够到喷嘴顶的同时，至少另两根指仍包住瓶身 0.44–0.54 段——跨越 ~45mm 高度差，而非等长指尖同面。
2. **拇指可做「过顶拱压」**：运动学上能把指腹送到瓶轴正上方、压轴近似竖直，落到 Ø22 喷嘴中心（对中误差 ≲ 10mm），并在该位姿持续输出下压力不后退。
3. **指尖力 ≥ ~8 N 且有裕量**（建议 ≥ 15–25 N），保持按压到底时不因反力滑脱。
4. **≥2 指独立包卷 Ø44**：带指外展 + 独立屈曲，能形成至少两点环抱作横向限位。
5. **必须落在臂可达姿态族内**：高度分工（1）、绕背（4）、拇指拱压（2）都须在当前 Kuka 过顶族内成立；若走侧向路线，先解决 7.1 第 2 行的臂/瓶位问题，与手无关。

### 7.3 仓库内可用的更高灵巧候选：Shadow Hand

- 库内已有 `SHADOW_HAND_CFG`（`isaaclab_assets/robots/shadow_hand.py`，24-DoF，含腕 WRJ0/1），部分关节铭牌 effort 更高（腕 ~4.8 N·m、THJ4 ~2.4 N·m、多数指节 0.72–0.9 N·m），确有逐指独立屈曲 + 拇指多 DOF 对掌，能覆盖 7.1「绕背 / 拇指对掌」两行。
- **但它是独立手资产，未挂载到任何臂组合**；整体尺寸约人手级、指节不比 Allegro 更长，未必满足 7.2-1 的 45mm 高度分工。
- 指尖能否持续 ≥8 N 顶住 2000 N/m 弹簧并保持到位，属力量项，仍需实测——灵巧度本身不保证力量达标。

### 7.4 判定

换更高灵巧的手能解决**灵巧类**瓶颈（逐指绕背、拇指对掌拱压、手内重抓），但解决不了**尺寸 / 臂工作空间 / 力量类**瓶颈（45mm 指长差、Kuka 过顶姿态族、≥8 N 触发力）。在「Kuka iiwa7 + 固定瓶位」前提下，即便换手仍须同时满足 §7.2 全套几何 + 力量规格，而其中**指长高度分工（7.2-1）与臂姿态可达（7.2-5）两条不随手而变，是硬约束**。

→ **结论维持：本配置下「一次握持内环抱瓶身 + 拇指压顶」不可行，换更高灵巧手不改变该结论。** 若仍要「握持中按压」，应从备选路线 A–D（§5）整线重定；「不同手 + 不同瓶位/臂」的专项评估本次未做，超出本评估范围。
